# 通知中心复刻说明

## 范围

本次实现以知乎 Android 11.3.0（40308）的真实页面和请求为基准，覆盖：

- 消息主页的四个通知分类、未读数、邀请回答入口和消息会话列表；
- 邀请回答的分页列表、日期分组、问题详情与写回答入口；
- 私信会话的分页读取、消息查看和文本发送；
- 既有通知显示偏好、未读角标偏好和自动已读偏好。

发起新会话、图片或贴纸消息、删除邀请等写操作不在本次范围内。通知设置仍由知乎++原有入口承担，不改变任何通知类型的默认开关。

## 取证与请求预算

取证使用本地 API 31 writable-system AVD、官方 APK、Reqable 移动端 CA 和导出的 HAR。HAR 只保存在临时目录，账号 Cookie、私信正文和用户标识不进入仓库。

每个页面的首屏请求预算如下：

| 页面 | 请求 |
| --- | --- |
| 消息主页 | `GET /notifications/v3/message/v3?limit=20`，后续每页一次 |
| 邀请回答 | `GET /notifications/v3/timeline/entry/invite?invite_with_time_slice=1&limit=20`，后续每页一次 |
| 通知分类 | `GET /notifications/v3/timeline/entry/{entry}?limit=20`，后续每页一次 |
| 私信查看 | 首屏并行请求 `GET /messages/user/{peer}` 与 `GET /messages?limit=20&sender_id={peer}`，后续每页一次消息请求 |
| 私信发送 | 用户每次点击发送只调用一次 `POST /messages`，成功后直接插入服务端返回的消息，不自动二次拉取 |

进入通知分类后，只有用户已经启用“自动标记已读”时才调用对应的 `actions/readall`；数据修复不改变默认偏好。

## 数据流

`message/v3` 的 `head` 提供四个分类及未读数，`column_head` 提供邀请回答入口，`data` 提供消息会话。邀请回答和普通通知分类共享时间线模型，但各自由独立分页状态持有。私信页面使用独立的消息模型和分页状态，不与通知时间线混合。

首页消息条目可能同时携带通知分类链接和 `inbox/{peer}` 链接。导航解析优先选择私信链接，否则才进入普通通知分类，避免把真实会话误当作通知时间线。

通知主页在首次进入和每次从二级页面返回前台时重新拉取首屏，使四个分类的未读数与服务端同步。文本私信按官方客户端协议先构造包含 `receiver_id`、`content`、`content_type=0` 和 `source_type=message_list` 的 form，再加密为请求体并标明协议版本；发送失败时保留草稿，成功时清空草稿。

## 兼容边界

- `column_head.avatar_urls` 是包含 `url` 与 `night_url` 的对象数组，不是字符串数组；模型按原始响应解码。
- 首页消息摘要是纯文本，不经过 HTML parser。
- 邀请卡片的奖励说明确认为 HTML 字段，只在这个已验证字段上提取可见文字。
- 已观察到的私信 `content_type` 为纯文本和带插件文本两类；未知接收类型保留降级文案，发送仅支持已验证的纯文本类型。
